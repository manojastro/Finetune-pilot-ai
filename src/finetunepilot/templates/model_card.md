# {repo_name}

A LoRA adapter for [`{base_model}`](https://huggingface.co/{base_model}), trained with QLoRA
(4-bit NF4 base model) to answer requests with one tool call in Qwen's native format:

```
<tool_call>
{{"name": "get_weather", "arguments": {{"city": "Madrid", "unit": "celsius"}}}}
</tool_call>
```

Made with [FineTunePilot](https://github.com/manojastro/Finetune-pilot-ai). All numbers below are
copied from the project's run logs; anything not measured says so.

## Results

Test set: {test_rows} held-out synthetic requests over 6 tools. Greedy decoding, both models
loaded the same way (4-bit), so the adapter is the only difference.

## Data

60 synthetic training rows generated by `scripts/make_sample_data.py`: 6 made-up tools (weather,
calendar, email, calculator, file search, currency). Train and test use different sentence
templates and argument values, and a test checks that no request appears in both.
Loss was computed on the tool call only, not on the prompt or tool schemas.

## How to use

```python
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

base = AutoModelForCausalLM.from_pretrained("{base_model}", device_map="auto")
model = PeftModel.from_pretrained(base, "{repo_id}")
tokenizer = AutoTokenizer.from_pretrained("{repo_id}")

tools = [...]  # OpenAI-style function schemas
messages = [{{"role": "user", "content": "What's the weather in Madrid in celsius?"}}]
prompt = tokenizer.apply_chat_template(
    messages, tools=tools, add_generation_prompt=True, tokenize=False
)
inputs = tokenizer(prompt, return_tensors="pt", add_special_tokens=False).to(model.device)
out = model.generate(**inputs, max_new_tokens=128, do_sample=False)
print(tokenizer.decode(out[0, inputs["input_ids"].shape[1] :], skip_special_tokens=False))
```

## Limitations

- Trained and tested on a tiny synthetic dataset (60 / {test_rows} rows, 6 tools). The scores
  say how well it learned *these* tools and phrasings, not general tool calling.
- One tool call per answer; no multi-turn tool use, no "no tool needed" cases.
- Arguments are compared exactly; a semantically equal but differently written value counts as wrong.
